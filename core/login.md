# 登入與 Token

平台登入做三件事:**驗證身分、決定你落在哪個組織(租戶)、發一張 JWT**。之後每個請求平台會**即時把角色注入**、並能**隨時讓既發的 token 失效**。

你通常不用自己寫登入 controller 或 token 驗證——但這條鏈有兩個非直覺點,是排查「為什麼被登出 / 為什麼改了權限沒生效」的關鍵:**角色不寫進 token**、**改密碼 / 改資料會讓那個人手上的 token 整批失效**。

---

## 登入模式

底層是「帳號 + 密碼 + 指定組織」,可再加掛多種模式 / 政策:

### 帳號密碼 + 組織

登入要帶 `Account` / `Password`,**外加 `OrgId` 或 `OrgKey` 指明落在哪個組織**。原因:**同一組帳號可以在多個組織各自存在**(各是獨立租戶的使用者),所以登入一定要消歧「這次是登進哪個組織」。

### 組織連結登入(OrgKey)

`OrgKey` 是**加密後的組織 id**,用來做「一條可分享、綁定單一租戶的登入連結」:

- **後端**:登入帶 `OrgKey` → 平台解密成該組織 → 完成租戶消歧(等同帶 `OrgId`,但不必把內部 id 攤在 URL 上)。
- **前端**:URL 以 `Org_{OrgKey}` 為前綴,**把整個前端 session 鎖在該租戶的 URL 空間**——在這個前綴下導航,離開時會自動補回前綴;想跳到「別的組織」會被擋下。未登入時也導向該組織的登入頁。
- **可分享連結**:平台提供「產生本組織登入連結」與「對指定組織產生連結」兩個入口,可出 QR code、複製、或用系統分享。使用者點連結就直接落在**那個組織**的登入頁。

> 典型用途:多租戶部署下,給每個組織一條「自己的登入入口」,使用者只要連結、不用知道自己屬於哪個組織 id。

### 代理登入(Proxy)

管理者可**以另一個使用者的身分操作**(常見於上層組織代登子組織)。平台會建立一個系統用的代理使用者、複製被代理者的群組與角色,後續以對方身分讀寫資料。

### IP 白名單限定登入(可選模組)

`Hcs.Platform.IpWhiteListOnlyLogin` 模組把登入綁到**來源 IP**:

- **白名單內的來源**:登入頁能看到組織下拉、可自由挑任意組織登入。
- **白名單外的任何來源**:登入頁的組織下拉是**空的**、一般帳密登入也被擋;**唯一入口是帶 `OrgKey` 的組織連結**(對組織連結登入直接放行)。

> 合起來就是常見的部署模式:**管理端(內網 IP)能切換任意組織登入,其餘租戶只能各自用自己的組織連結、進自己的組織**。

### 2FA / 第三方登入(可選模組)

二階段驗證、第三方(OAuth 等)登入是**可選模組**,掛在登入驗證鏈上或提供額外登入來源。2FA 見 [2fa](../modules/2fa.md)。

## 登入流程

1. **取組織清單**(登入頁下拉用):可被政策**收窄**——例如 IP 白名單模組會對白名單外的來源回空清單。
2. **送出登入**:平台解 `OrgKey`(若有)→ 查帳密 → 依序跑**所有登入 validator**(2FA、IP 白名單…**任一不過就擋**)→ 成功才發 JWT。
3. **反暴力**:每次回應帶**隨機延遲**、對「同一組織+帳號」上鎖串行、累計失敗次數,降低猜密碼 / 時間側信道的價值。

---

## Token 裡有什麼(關鍵:角色不在裡面)

JWT 只帶**使用者 id** 與標準欄位(簽發者 / 受眾 / 生效與到期時間 / token 唯一 id)。**它不帶任何角色 / 權限。**

每個請求通過 JWT 驗證時,平台**當場用 id 重新撈一次該使用者的角色**,注入成這個請求的角色資訊(有約 10 分鐘的記憶體快取緩衝)。

> 帶來的非直覺結果:**改了使用者權限,不必重發 token**——因為角色是每請求即時撈的,下一個請求(快取過後)就生效。代價是每請求一次角色查詢。授權怎麼用這些角色,見 [權限 / 角色樹](permissions.md)。

## Token 失效與撤銷(最常被問「為什麼突然被登出」)

Token 有兩種失效:

- **自然到期**:token 帶固定效期(預設 **3 天**,可由 `JwtConfigBuilder.IssueDays` 調整),到期前可用 **refresh token** 換一張新的(順便撈到最新資料 / 角色,延續 session)。
- **伺服器端即時撤銷**:平台為每個使用者記一個「**資料最後異動時間**」,**每次 token 驗證都比對**——只要 token 的簽發時間早於這個異動時間,就判失效。

所以:

> **改了某使用者的資料 / 密碼 / 停用帳號 → 那個人手上所有既發的 token 立刻整批失效**,下一個請求就被踢回登入。這是伺服器端機制,**與前端有沒有清掉本地 token 無關**。

觸發「資料異動時間」更新的時機:**管理員改 / 刪使用者**(即時),以及**使用者自助改密碼**。

> 自助改密碼有個刻意的不對稱:它會**踢掉你其他裝置的 session**(它們持的是舊 token),但**當場回一張新 token 給你自己**——所以改密碼者的目前 session 會換上新 token 續命、不會把自己一起踢掉。

## Gotchas 一覽

- **角色不入 token**:後端改權限即時(過 10 分快取)生效;但**前端記的角色是登入當下存的**,要重新登入或 refresh token 才更新。後端已生效、前端尚未,是正常的不對稱,不是 bug。
- **改密碼 / 改資料 → 整批 token 失效**是**伺服器端**判定,不靠前端配合;反過來,光在前端清 token 不等於伺服器端撤銷。
- **OrgKey 連結會鎖定租戶**:在 `Org_{OrgKey}` 前綴下,前端 session 綁死在那個組織;要換組織得走**另一條**組織連結,不能在 app 內直接跳。
- **IP 白名單外只能用組織連結**:白名單外來源的登入下拉是空的、一般登入被擋,務必給對應組織的連結當入口。
- **同一帳號跨組織**:`Account` 不是全域唯一,(帳號 × 組織)才是;登入務必帶 `OrgId` / `OrgKey`,否則無從消歧。
